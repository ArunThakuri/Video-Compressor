How it works

What does the patcher actually do?

It parses the MP4 box tree, rewrites moov, and rebuilds the file. Three edits: mvhd duration is set to the all-ones “unknown” sentinel (widening the box from v0 to v1), a ©too encoder tag is written under moov/udta/meta/ilst, and every stco/co64 chunk offset is recomputed because moov changed size.

The sample tables are expanded and re-validated first, so a file whose tables disagree is rejected instead of being written out corrupt.

Does this re-encode my video?

No. The coded frames and audio samples are copied byte-for-byte — only container metadata changes. That is why it takes milliseconds and why there is no quality loss: nothing is encoded a second time. Verify it yourself by hashing the elementary streams before and after.

Why was my file rejected?

The usual reason is an inconsistent export — a variable-frame-rate file whose stsz, stsc, stts and stco tables no longer agree. Re-export at a constant frame rate and it will patch. Fragmented MP4s (moof) and non-H.264/HEVC video are also refused.

Where do my files go?

Nowhere. There is no upload and no server — the file is read with the File API, patched in this page, and handed back as a download. Nothing leaves the machine. The recent list lives in memory and is gone when you close the tab.
